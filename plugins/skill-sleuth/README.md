# skill-sleuth

The English edition. It finds the right Claude skill for a task across five layers (session listing, local index, claude.ai, MCP, consent-gated third-party registries). For every skill or plugin candidate that is not installed it shows the source, install count, GitHub stars and age, and filters out new and unpopular ones. Skills you already have are used right away; anything new is installed only after a numbered "yes". It never runs a third-party skill's own scripts or hooks until you approve installing or testing that skill.

The skill lives in `skills/skill-sleuth/`. Do not install it together with `skill-bulucu`, the Turkish edition.

Install it inside a Claude Code terminal session (2.1.275 or later):

```
/plugin install skill-sleuth --marketplace ssakkaya/skill-sleuth
```

In the Claude Desktop app, or on older versions, run in a terminal: `claude plugin marketplace add ssakkaya/skill-sleuth`, then `claude plugin install skill-sleuth@skill-sleuth`. Other install options, privacy notes and limits: https://github.com/ssakkaya/skill-sleuth

## What it does

- **When it runs.** Its description asks Claude to use it when you ask which skill or plugin fits a task, whether one exists, or to find or install one, and when a task needs a file format, tool or service that no skill in the session's listing covers. Turn it off in `/plugin` > Installed, or with `claude plugin disable <id>`; `claude plugin list` shows the id: `skill-sleuth@skill-sleuth` when installed from GitHub as above, `skill-sleuth@claude-community` from Anthropic's community marketplace, `skill-sleuth@synced` when added on claude.ai, for example from the plugin directory (remove that copy on claude.ai under Customize > Plugins).
- **Each run.** It reads the skill listing of the current session; runs the offline local index `scripts/skill_ara.py`; uses the claude.ai skill and plugin search tools and MCP `skill://` resources when the session offers them, and, when the session offers it (observed only in the Desktop Code tab), the claude.ai connector directory when a task needs a service that no tool in the session covers; and searches third-party registries with `scripts/dis_kaynak_ara.py` only after you agree. It ends with a short report (Mode, Needs, Candidates, Chosen, Obtained, Skipped, Eliminated, Persist).
- **Programs it runs.** The four Python scripts in `skills/skill-sleuth/scripts/` (standard library only, readable source), started with `python`, `python3` or `py -3`. Two of them, `katalog_indeksle.py` and `skill_envanteri.py`, are offline diagnostics, used as a fallback listing and for troubleshooting. No script starts another program. From the settings files the scripts use only `enabledPlugins`, `skillOverrides` and `disableBundledSkills`, merged as Claude Code merges them: `~/.claude/settings.json`, then the current project's `.claude/settings.json` and `.claude/settings.local.json` (on macOS and Linux also the one at the git root). To find a git root they check whether a `.git` entry exists in the current folder and its parents (and in the project folders that plugin install records name), and read the one-line pointer file a git worktree has there; they never open Claude Desktop's own config file (`claude_desktop_config.json`, which can hold MCP server secrets). To find the Claude Desktop data folder on Windows they check which of `%APPDATA%\Claude`, `%LOCALAPPDATA%\Claude-Data\<id>` (observed 2026-10-22) and `%LOCALAPPDATA%\Packages\Claude_<suffix>\LocalCache\Roaming\Claude` holds a `local-agent-mode-sessions` folder, and when that folder last changed. In claude.ai chat (`/mnt/skills`) no script runs.
- **What Claude reads without asking.** To tell the Desktop app, a terminal and an unattended run apart, Claude reads four environment variables (`CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_EXECPATH`, `AI_AGENT`, `CLAUDE_CODE_CHILD_SESSION`; the executable path contains your OS user name) and the current session's `~/.claude/sessions/<pid>.json` (kind, entrypoint, version, working folder), and checks whether the claude.ai sync manifest and the Desktop app's plugin manifest exist (their folder names contain your claude.ai organization and account ids, or their first 8 hex digits). To pick the `claude` binary for an approved command it lists the Desktop app's `claude-code` folder (Windows: the newest `claude.exe`), else uses `claude` on your PATH. What it reads stays in the conversation; nothing of it is sent anywhere.
- **Commands Claude runs without asking.** Read-only, offline Claude Code commands: `claude --version`, `claude plugin list --json` (also with `--available`), `claude plugin details <name>` (for a plugin that is not installed: `claude --plugin-dir <plugin folder in the marketplace clone> plugin details <name>`), and, during a pre-install review, `claude plugin validate <folder>` on a clone you allowed, plus short `python -c` one-liners that read `enabledPlugins` or filter `plugin list --json` output. They change no settings or plugins.
- **Skills it follows.** When it uses a skill that is not in the session's listing, it reads that skill's SKILL.md from your disk (or from an MCP server you connected) and follows it. It runs that skill's scripts only when the skill is in your own skills folder or Anthropic's official marketplace clone (which also carries some partner plugins under `external_plugins/`). It never follows a third-party skill from the internet: that SKILL.md is read only as data during the pre-install review, its scripts and hooks never run, and the skill can be used only after you install it with a numbered yes.
- **Changes it makes, only after a numbered "yes".** `claude plugin install` (it also installs and enables the plugin dependencies named in the consent block), `claude plugin marketplace add` (a community-catalog plugin needs two separate yeses), enable, disable, uninstall, update, `claude plugin prune`, `claude plugin marketplace update` or `claude plugin marketplace remove` (which also uninstalls every plugin from that marketplace), or copying a skill folder into `~/.claude/skills/<name>/` or `<project>/.claude/skills/<name>/`. Installing changes `enabledPlugins` in the settings file of the scope you pick (`~/.claude/settings.json`, `.claude/settings.local.json` or `.claude/settings.json`). Adding a marketplace writes `extraKnownMarketplaces` to `~/.claude/settings.json` and records it in `~/.claude/plugins/known_marketplaces.json` (under `$CLAUDE_CONFIG_DIR` when set; plugin files under `$CLAUDE_CODE_PLUGIN_CACHE_DIR` when set). To test a skill that is not in the listing it may start a separate Claude Code process (`claude --plugin-dir <path>`, or `claude -p` with a temporary command file in the project's `.claude/` folder), also only after a yes. Nothing of this happens in unattended runs (`claude -p`, Agent SDK, scheduled tasks, subagents).
- **What it never does.** It never changes permission settings, never writes a hook into your settings (on request it only shows a reminder hook you may add yourself), never runs `npx` or a package install itself, never connects a connector itself (you connect it from its card), never asks for or handles tokens or other credentials, and never runs a third-party skill's scripts or hooks before you approve installing or testing it. A plugin you approve runs its hooks, mods, monitors, MCP/LSP servers and `bin/` with your permissions, and when it has a `package.json` with a lockfile, Claude Code runs `npm ci --ignore-scripts` for it at install. For a skills.sh hit it only shows the `npx skills add …` command for you to run; if `pyyaml` is missing it tells you the `pip install pyyaml` command and does not run it.

## Network requests

Only `scripts/dis_kaynak_ara.py` connects to the network; the other three scripts never do. It sends read-only HTTPS GET requests with the User-Agent `skill-sleuth/0.1 (+skill search)` and no token, cookie or `Authorization` header, only to these three hosts (requests to any other host, redirects included, are refused). Per run: at most 18 requests (plus 9 SKILL.md lookups at standard paths that miss; redirects within the three hosts are followed and not counted), each with a 15-second timeout, and no new request after 75 seconds. The hosts see your IP address.

| Host | What is requested | What leaves your machine | When |
|---|---|---|---|
| `skills.sh` | `/api/search?q=…` and `/api/v1/skills/audit/<owner>/<repo>/<skill>` | 2-6 generic English keywords Claude derives from your task; the ids of skills it returned | Only after you agree to a third-party search, or when you ask for one |
| `raw.githubusercontent.com` | The public catalog `anthropics/claude-plugins-community/.claude-plugin/marketplace.json` (searched locally); a candidate's `SKILL.md` at a pinned commit | Public repository names, file paths and commit hashes | During an agreed third-party search; the catalog only when the cached copy is missing or older than 24 hours, and once more (`--refresh`) before a community-catalog install is offered |
| `api.github.com` | `repos/<owner>/<repo>` (stars, age, archived, license), `commits`, `git/trees` | Public repository names, file paths and commit hashes | **Without asking:** one `repos/<owner>/<repo>` request (stars, age) before it shows a not-installed catalog, claude.ai or dependency candidate (`--repo`, at most 3 per task, cached for 7 days), only in a task where you asked about skills or plugins; and one for a repository you name to install (Claude then reads that repository's files at a pinned commit itself, see below). The other requests only during an agreed third-party search |

Before any request the script rejects queries that look like data (shorter than 2 or longer than 80 characters; more than 8 words; characters other than letters, digits, space and `+ # -`; a number of 5 or more digits; more than 6 digits in all; or more than one all-digit word). No file contents, local paths, file names or inventory are sent. GitHub is queried without a token: 60 requests per hour per IP address.

Claude itself, with its own tools and not through the scripts, may also contact these services:

- **Pre-install review of a candidate, before the install question:** it reads the candidate's public files at a pinned commit from `raw.githubusercontent.com` (e.g. `plugin.json`, `hooks/hooks.json`, `monitors/monitors.json`, `.mcp.json`, `.lsp.json`, `settings.json`, `SKILL.md`; the same for each declared dependency) and a directory listing from `api.github.com` (for a repository you name, also its latest commit id); for a hit from a third-party search you agreed to or asked for, it may also open its skills.sh audit entry; and only with your permission it makes a shallow sparse `git clone` from the candidate's git host into the session's temporary folder to read a script (never to run it).
- **After a numbered yes:** `claude plugin install`, `claude plugin update`, `claude plugin marketplace add` and `claude plugin marketplace update` download the plugin or marketplace from its source, the plugin's declared dependencies and, for a plugin with a `package.json` and lockfile, its npm packages.
- **Anthropic and MCP tools you already have:** claude.ai `SearchSkills` / `SearchPlugins` and the `SuggestSkills` / `SuggestPluginInstall` cards (a few search words go to claude.ai) when the session offers them, and `skill://` resources of MCP servers you have already connected.
- **The claude.ai connector directory** (`search_mcp_registry` and `suggest_connectors` of the `mcp-registry` server; observed in the Desktop app's Code tab on 2026-10-14, unverified in claude.ai chat): only when a task needs a service, such as a calendar, that no tool in the session covers, even if a listed skill fits. At most one search per task, with at most 4 English words (the service's public product name and one generic noun; the name of an internal or private system is left out; never personal data, names of people, customers or projects, file names, paths, URLs or e-mail addresses); they go to claude.ai. The result shows whether each matching connector is connected on your claude.ai account. The whole result, with every match's connection flag, returns into the conversation like any tool result; Claude repeats only the name, a short description, the connected flag, the directory id and the server host, and never prints the raw response. A directory connector has no repository, so no GitHub request is made for it. For a matching connector that is not connected, Claude may show one `suggest_connectors` card with up to 3 connectors (never in unattended runs). You click Connect; the service may show its own permission screen, where you approve the permissions (unverified; only the card was observed). Once connected, the connector's server can read and act on (write or delete in) your account on that service, within the permissions you approve. Claude never connects or turns on a connector itself and never asks for or handles tokens or other credentials. Whether a connector connected this way works in the running session is unverified; if it does not, start a new session.

Nothing is sent to the author of this plugin, and there is no telemetry.

## Files it writes

By default all script output goes to one cache folder, never into the plugin folder: `%TEMP%\skill-sleuth` on Windows (inside your per-user temp folder), `~/.cache/skill-sleuth` on macOS/Linux (`$XDG_CACHE_HOME/skill-sleuth` if set, created with mode 0700; a folder or file owned by another user or writable by group or others, or a cache file that is a symlink, is not used). The `--out`, `--cache` and `--cache-dir` options and the `$SKILL_ARA_CACHE` and `$DIS_KAYNAK_CACHE_DIR` variables can point elsewhere; the skill's run instructions do not pass them. Even then nothing is written into a Claude config tree (a `.claude` folder, `~/.claude.json`, `$CLAUDE_CONFIG_DIR`, `$CLAUDE_CODE_PLUGIN_CACHE_DIR`), and the index cache never replaces a file that is not its own: such a path is refused with a `not:` line (for `dis_kaynak_ara.py --cache-dir`, with exit 2), and no folder is created there. Files are written through a temporary file and an atomic rename.

| File | Written by | Contents |
|---|---|---|
| `skill_ara_cache.json` | `skill_ara.py` (every run that rebuilds the index) | Local index: names, descriptions and full paths of the skills and plugins on your disk (paths contain your OS user name), your plugin and marketplace lists, the `enabledPlugins` and `skillOverrides` values in effect, the Claude config, plugin and Claude Desktop folders it searched, the project skill folders it found and any folder you point it at with `--root` (not the current folder itself). Your claude.ai organization and account ids are part of two kinds of folder names (in the Desktop app's plugin folder, observed 2026-10-22, only their first 8 hex digits), so the stored paths contain them and `--show` prints such a path into the conversation: the Claude Desktop app's own skill and plugin folders (on Windows under `%APPDATA%\Claude`, `%LOCALAPPDATA%\Claude-Data\<id>` (observed 2026-10-22) or `%LOCALAPPDATA%\Packages\Claude_<suffix>\LocalCache\Roaming\Claude`, whichever holds them; `~/Library/Application Support/Claude` on macOS, `$XDG_CONFIG_HOME/Claude` or `~/.config/Claude` on Linux; under `$CLAUDE_DESKTOP_DATA_DIR` instead when set) and the claude.ai sync folder `~/.claude/skills/synced/<org>_<account>/` (under `$CLAUDE_CONFIG_DIR` when set) |
| `community-marketplace.json` | `dis_kaynak_ara.py` | A copy of the public community catalog (up to 16 MB) |
| `dis_kaynak_github.json` | `dis_kaynak_ara.py` | Public GitHub data of candidate repositories: stars, forks, dates, archived flag, license, file lists, commit hashes |
| `02-skill-envanteri.json`, `02-skill-envanteri-ozet.json` | `skill_envanteri.py` (diagnostics) | Inventory of the SKILL.md and plugin command files in the Claude Code, Claude Desktop skill and plugin, and project folders (plus any folder you add with `--extra-root`), with paths (which can contain your claude.ai ids) and descriptions, plus your `enabledPlugins` and `skillOverrides`, the paths of the settings files read, installed plugin ids and marketplace folder paths. Cowork scheduled tasks, Cowork session uploads and other tools' folders such as `~/.codex` are not scanned |
| `03-katalog-indeksi.json`, `03-katalog-ozeti.md` | `katalog_indeksle.py` (diagnostics; not written with `--no-write`) | Index of the plugin catalogs on your disk, with install records, enabled plugin ids and the marketplace clone paths |

Outside the cache folder only what you approve with a numbered yes is written: installed plugins and their records under `~/.claude/plugins/`, added marketplace clones, the settings entries listed above, copied skill folders, and for a test run a temporary command file in the project's `.claude/` folder (the separate Claude Code process also writes Claude Code's own usual files and may sync your claude.ai skills into `~/.claude/skills/synced/`); plus, with your permission, a sparse clone in the session's temporary folder. A pre-install review is kept in the conversation, not in a file.

## Data retention

- The cache stays on your computer; the plugin uploads none of it and stores nothing on any server. The services it contacts (skills.sh, GitHub or a candidate's git host, claude.ai for its search tools, MCP servers you connected and, after an approved install, the plugin's source and npm) may log those requests (search words, repository names, your IP address) under their own policies.
- The local index is rebuilt when it is older than 24 hours or your skill setup changes. The community catalog copy is refreshed after 24 hours and once before a community-catalog install is offered (an older copy is used only when a download fails). GitHub data expires after 60 minutes (latest commit), 24 hours (file lists, first-commit dates) or 7 days (stars, age), and expired entries are removed when the file is next saved.
- The scripts never delete the cache folder, and uninstalling the plugin leaves it behind. Delete it yourself: `Remove-Item -Recurse -Force "$env:TEMP\skill-sleuth"` (Windows PowerShell) or `rm -rf "${XDG_CACHE_HOME:-$HOME/.cache}/skill-sleuth"` (macOS, Linux).
- Plugins, marketplace clones, settings entries and skill copies you approved stay until you uninstall or delete them.
- A connector you connect from a card stays connected on your claude.ai account until you disconnect it in the claude.ai connector settings; whether that also ends the access you approved on the service is unverified (you can revoke it in that service's account settings).

## Example prompts

- "Which skill should I use to turn the tables in this PDF into an Excel sheet?" It looks at the skills you already have and uses the fitting one right away.
- "Is there a plugin that checks KiCad PCB files? Look in third-party registries too." It first tells you which search words go to skills.sh and the community catalog, then searches and shows each candidate's source, installs, stars and age, and the ones it eliminated.
- "Find a skill for making slide decks and install it if it fits." It reviews the candidate and installs it only after you answer a numbered question.
