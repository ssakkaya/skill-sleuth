# tests/

Offline unit tests, standard library only (Python 3.9+). CI runs them on Linux, macOS and Windows with Python 3.9 and 3.12:

```
PYTHONUTF8=1 python -m unittest discover -s tests -v
```

Run from the repository root. PowerShell: `$env:PYTHONUTF8=1; python -m unittest discover -s tests -v`.

| File | What it covers |
|---|---|
| `test_skill_ara.py` | 2 KB output cap (text, `--json`, `--show`); `--max-bytes` below 300 is exit 2, and the cap holds with a long query and three `not:` lines; malformed frontmatter and non-UTF-8 files; lone surrogates (`\ud800` escapes) in JSON files; changed Claude Code file formats; the project walk stops at the home folder; parallel cold runs on one cache; symlinked skill folders and link cycles; Windows junction cycles, also without `os.path.isjunction` (Python < 3.12); self-exclusion and the both-editions note; Claude Code's load rules: `enabledPlugins` / `skillOverrides` merged from the user, project and local settings, only the live plugin-cache version folder (`installPath`, no `.orphaned_at`), a plugin's default `skills/` plus its declared paths or a root `SKILL.md`, one-level skill folders, a marketplace clone never callable, an installed plugin without skills never offered for install, a JSON file with a BOM, a capital `İ` and three-letter stems in the search; round two: skills-dir plugins and `<name>@skills-dir: false`, the marketplace entry's skill paths, install records of another project, sanitized cache folder names, a clone copy never replacing the callable one, `--show` of an installed plugin, bundled skills under `skillOverrides` / `disableBundledSkills`, ghosts of the other edition, ancestors up to the git root, local settings at the git root (macOS / Linux); hidden characters; catalog markers; the cache's roots object keeps only the four compared roots (no cwd or project_dirs; project skill folders that exist are still stored), it rebuilds when a root changes, and it never replaces a foreign file, a `.claude` path or a non-`.json` path, nor blocks on a FIFO |
| `test_dis_kaynak_ara.py` | privacy guard (every rule, both sides of each limit); offline exit 3; argument errors; a `--cache-dir` in any Claude config tree is exit 2 and creates nothing; the community catalog from a synthetic cache: trust lines, elimination, byte cap; a scripted HTTP layer (no socket): a GitHub 5xx is an outage (install command kept, `--repo` exit 3), hidden characters in frontmatter values and audit summaries (`--show`, `--audit`), malformed skills.sh JSON, plugin markers for monitors / LSP / settings |
| `test_cache_safety.py` | default cache folder per OS; refusal of folders and files another user owns, group/others can write, or that are symlinks (macOS/Linux); nothing is written into a Claude config tree (`.claude`, `$CLAUDE_CONFIG_DIR`, case-insensitive), links included; the shared helper functions are identical in all four scripts |
| `test_inventory_scripts.py` | `katalog_indeksle.py` and `skill_envanteri.py` on synthetic trees: fields of unexpected JSON types (a plugin `source` that is a number or a list, a `scheduledTasks` that is not a list, non-numeric or infinite `unique_installs`), lone surrogates, Windows junction cycles without `os.path.isjunction`, a bad `--today`; everything printed goes through scrub() (hidden characters show as `?`), `katalog_indeksle.py` strips them from descriptions and adds `GIZLI-KARAKTER(n)`, both merge local-scope `enabledPlugins` and the inventory gives no tool name to a left-behind version folder or a nested `SKILL.md`, the clone `git` fields are gone, and Cowork tasks, `~/.codex` and the Desktop config file are not listed |

| `test_repo_tools.py` | scripts byte-identical across the two plugins; frozen frontmatter; `tools/build_yayin.py --check` passes here and fails on CRLF/BOM, personal data, version drift, script drift, stray files, size caps, a plugin `LICENSE` that is missing or differs; a build copies the `LICENSE` and a dry run reports it; reproducible zips; `--zip` without DIR writes `dist/v<version>/` (`.zip` + identical `.skill`) and `dist/` is not checked; no script starts a program or names the Desktop config file; the invisible-text helpers are identical; each edition prints reference file names that exist; the User-Agent is quoted in the READMEs |

Isolation: each test builds a throw-away machine with `tempfile.mkdtemp()` and points `HOME`, `USERPROFILE`, `CLAUDE_CONFIG_DIR`, `CLAUDE_DESKTOP_DATA_DIR`, `XDG_CACHE_HOME`, `XDG_CONFIG_HOME`, `APPDATA`, `LOCALAPPDATA` and `TMPDIR`/`TEMP`/`TMP` into it. The real home folder, Claude config, desktop app data and cache are never read or written; `dis_kaynak_ara.py` runs with `DIS_KAYNAK_TEST_OFFLINE=1`, except in the scripted-HTTP tests, which replace urllib's opener inside the child process; either way no request leaves the machine. Tests that need symlinks or POSIX permissions skip where the OS does not allow them; junction tests run on Windows only and remove their junctions before the sandbox.

Scripts under test: `plugins/skill-sleuth/skills/skill-sleuth/scripts/`. To test another copy (for example a source edition before `tools/build_yayin.py` regenerates the plugins), set `SKILL_SCRIPTS_DIR` to its `scripts/` folder.
